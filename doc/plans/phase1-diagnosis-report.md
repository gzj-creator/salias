# Salias 64B 广播吞吐 Phase 1 诊断报告

**执行日期**：2026-10-19（Asia/Singapore）

**基线版本**：v3.0.0 / `c5e6aa7df4397df6f47a4e00cf5f72ed5ae778bd`

**执行人**：Codex

**状态**：实验、工具与报告完成；稳定性及插桩扰动门禁未通过，不宣称根因已确认。

## 一、执行摘要

100M 消息长测仍复现“小包反而更慢”：Salias 64 B 中位数 6.489 Mmsg/s，
Aeron 49.525 Mmsg/s，差距 **7.63 倍**。但 Salias 64 B 五轮变异系数 13.78%，
未达到 <5% 门禁。插桩时背压极低，未观测到 H1 的预期信号；64/256 B 的帧步长
分别为 72/264 B，均为 8 mod 64，且 64 B 周转更少。成功 `try_claim` 计时不能
单独归因 Guard，计数及逐条计时还显著改变吞吐。**不批准直接进入产品优化；
有条件优先 Phase 2B 单发布者快速路径的隔离实验，须先完成低扰动及拓扑对照。**

## 二、延长轮次基线

数据：`build/benchmarks/baseline-extended-20261019-183822/summary.json`。
72 次运行，含 60 次正式与 12 次预热；吞吐每组一轮预热、五轮正式，各 100M 消息。
下表“±”为五轮**样本标准差**，CV 为标准差/均值，不是置信区间。

| Payload | Salias 中位数 ± s（Mmsg/s） | Aeron 中位数 ± s（Mmsg/s） | Salias:Aeron | Salias / Aeron 时长（s） | CV：Salias / Aeron |
|---|---:|---:|---:|---|---|
| 64 B | 6.489 ± 0.958 | 49.525 ± 1.439 | 1:7.632 | 12.318–16.302 / 1.946–2.108 | 13.78% / 2.91% |
| 256 B | 15.465 ± 0.837 | 17.808 ± 0.217 | 1:1.152 | 6.176–7.170 / 5.515–5.663 | 5.46% / 1.21% |

**验收判定**：差距仍存在，但“所有组 CV<5%”“64 B 比例在 1:6–1:7”均未通过。
仅 Salias 64 B 每轮 >8 s；固定 100M 时，约 50 Mmsg/s 的 Aeron 本来就只需约 2 s，
因此没有擅自增加消息数以凑齐门槛。所有运行成功，无 timeout/OOM/内存 high/max 事件。
初始已编译 Salias 二进制在插桩前冻结保存，基线不使用修改后的比较器。

## 三、插桩诊断

最终数据：`build/benchmarks/diagnostic-20261019-185329/diagnostic_summary.json`。
每 payload 的 off/counters/timed 各一轮预热、五轮正式，共 36 次；每轮 10M 消息。
off 使用冻结的未插桩二进制；另两种使用同一新版二进制。各 worker 独占缓存行，
在本地累计，结束后才写匿名共享 mmap；不增加原有重试/yield 次数。
表内均为五轮中位数，消费者指标分两种模式保留，**不将不同运行的指标拼成一条记录**。

| Payload / 模式 | 背压率 | 空 poll 率：C0 / C1 | 成功 poll 平均批次：C0 / C1 | claim 平均耗时（ns） |
|---|---:|---:|---:|---:|
| 64 B / counters | 0% | 19.38% / 18.93% | 2.745 / 2.842 | 未计时 |
| 64 B / timed | 0% | 21.77% / 22.19% | 1.798 / 1.864 | 198.910 |
| 256 B / counters | 0.001670% | 17.86% / 17.88% | 2.845 / 2.706 | 未计时 |
| 256 B / timed | 0.000810% | 24.45% / 22.45% | 1.842 / 1.808 | 183.558 |

- **H1 背压过频（>10%）**：未获支持；64 B counters 最大单轮仅 0.000030%。插桩改变供需关系，不能据此严格排除未插桩时的背压。
- **消费跟不上**：未获支持，所有组空 poll 中位数 <50%；而且“空 poll >50%”本身也可能是发布侧供给不足，不是消费落后的充分证据。此问题不是原计划 H2 的定义。
- **H3 单发布者冗余同步**：未确认。64 B timed 的 claim 均值中位数未超过 200 ns（轮次范围 182.126–207.409 ns）；该值包含完整成功 `try_claim`、时钟读及调度影响，不等于 Guard 耗时。

**扰动门禁失败**：按同轮、同 payload 与冻结 off 配对，counters 的吞吐变化中位数
为 64 B **−20.46%**、256 B **−48.81%**；timed 为 **−38.04% / −54.59%**，
均远超 5%。off 对照还混合了重新编译后的代码布局影响，因此不能把全部差异视为计数指令成本。
先前共享计数及本地计数两个实现也各完整保留 36 次实验，未选取表现较好的一组冒充最终结果。

## 四、帧步长

依据 `src/core/frame/header.hpp`、`codec.hpp`、`shared_hybrid_mpsc.hpp` 与 `magic_ring.hpp`：
无 TTL 时为 `8 + align_up(payload, 8)`，双映射 ring 跨尾不写 padding。
数据：基线目录 `frame-layout.json`；均按 100M 消息、1 MiB ring 计算。

| Payload | 步长 | 步长为 64B 倍数 | 周转量（总字节/容量） | 64/步长（字节密度） | 最大在途完整帧 |
|---|---:|---|---:|---:|---:|
| 64 B | 72 B | 否 | 6,866.455 | 0.889 | 14,563 |
| 256 B | 264 B | 否 | 25,177.002 | 0.242 | 3,971 |

两者帧头起点均遍历 0/8/…/56 mod 64，8 B 帧头自身不跨 cache line。
64 B 的周转量仅为 256 B 的 **27.27%**，不是 >2 倍。
**H2“非对齐是 64 B 特有根因”未确认**；只能确认两者步长均未按 cache line 对齐。

## 五、下一步决策与边界

优先做同二进制 off/counters/timed 与稀疏计时的低扰动验证，再用未插桩的
1P1S/1P2S/1P3S、相邻 payload 扫描分离订阅者扫描与帧布局效应。
若仍指向发布侧，再进入 **Phase 2B**，用隔离构建验证 Guard 的专属贡献；预期机制是
减少单写者冗余同步，而非声称已测得收益。必须保留注册代际互斥、最慢订阅者背压、
payload 借用期及批量连续提交前缀。2A 需要先证实背压，2C 需要相邻 payload/对齐实验支持。

资源配置保持 CPU0–3、C0=CPU1、C1=CPU2、P=CPU3、协调器及 Aeron driver=CPU0；
ring/term=1 MiB、batch=1、poll-limit=64、Nice=5、MemoryHigh=640M、MemoryMax=704M、
swap=0。Aeron 为三 term，且多一个 driver，不是总映射内存或总 CPU 成本相等。
原 runner 的延迟测试仍为 2M 消息、1M/s、采样 1/16；这里只用其吞吐组归因。
只核验消息/采样数量，不做完整 payload/序列正确性证明。所有修改均在 `doc/`、`tools/`
及变更记录中；`src/` 无修改，未实施 Phase 2、未打 tag、未推送。
