6. offer() 的双重调用链

位置：src/salias/src/channel.cpp:1725 → mpsc.hpp:318 → claim() + commit()

// Publisher::offer()
auto offered = tx.offer(payload);  // 第 1 层

// MpscChannel::Tx::offer()

std::memcpy(...);

对比 Aeron：
// Publication::offer() 一步到位
int64_t offer(const uint8_t* buffer, size_t length) {
    int64_t position = m_appender->claim(length, m_bufferClaim);
    if (position < 0) return position;

    memcpy(m_bufferClaim.buffer(), buffer, length);
    m_bufferClaim.commit();
    return position;
}

问题：虽然可能被内联，但增加了调用栈深度和寄存器压力。

修复建议：
- 标记 Tx::offer() 为 [[gnu::always_inline]]
- 或者提供 fast-path API（用户直接调用 claim() + commit()）

7. False Sharing 风险

位置：src/salias/src/channel.cpp:79-108 (NamedControl)

struct alignas(kCacheLineGuard) NamedControl {
    std::uint32_t magic = 0;
    std::uint32_t version = 0;
    std::uint32_t mode = 0;
    std::uint32_t flags = 0;
    std::uint64_t capacity = 0;
    std::uint64_t record_size = 0;
    std::uint32_t ready = 0;
    std::uint32_t wait_word = 0;  // ← 生产者写
    std::byte pad[kCacheLineGuard - 40]{};

    alignas(kCacheLineGuard) std::uint64_t producer_pos = 0;  // ← 生产者写
    // ...
};

检查结果：你的实现是正确的！
- producer_pos 和 consumer_pos 已经分别 128 字节对齐
- wait_word 在第一个 cache line，但只在 commit 时写入（可接受）

潜在风险：wait_word 和其他只读字段共享 cache line，在高频 commit 时可能失效读缓存。

优化建议（低优先级）：
alignas(kCacheLineGuard) std::uint32_t wait_word = 0;
std::byte wait_word_pad[kCacheLineGuard - sizeof(std::uint32_t)]{};
