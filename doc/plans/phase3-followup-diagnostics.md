## 2. HFT 历史证据分析

输入固定为 `build/benchmarks/p3-p31-acceptance-20261021-155122/hft-tail-formal/`。
先复核原 manifest、输入/客户端/原始日志 SHA 与全部 96 轮，再生成独立诊断输出。

验收要求：

- 保留 4 个 S 臂不完整轮次，逐发布者报告 unsent、重试、背压、排期积压和资源计数。
- 区分 1 秒 progress 观测、实际截止与排空结束；不能把陈旧快照直接当作截止状态。
- 保留全部 subscriber 及 publisher，不跨配置/组池化，不相减独立分位数。
- 只报告可验证事实。没有同消息阶段与同步调度 trace 时，不认定宿主调度或缓存根因。
- 合成测试覆盖身份损坏、不完整输入、角色结构和误归因边界；主 agent 独立复核关键数值。

## 3. P3-2 假设与采集协议

假设：真实应用的多线程进程会使 `shared_ptr` 计数进入原子路径，而单线程子进程基准可能
没有覆盖这部分成本。ST/MT 差异也可能包含 libc 与其他运行时行为，不能全归因于引用计数。

生成独立诊断客户端，基于未修改 v3 benchmark 源码链接当前产品库。只在 publisher 的
正常 fork 后执行路径中可选启动一个休眠 helper，不在 atfork 回调中创建线程，不让 helper
发布、忙等或争抢共享对象。ST/MT 使用同一个客户端，仅环境变量切换，产品屏障模式固定为 A。
发布前验证实际线程数及可用时的 libc 单线程状态；所有控制行与原始 stdout/stderr 留存。

### 3.1 矩阵（第一条正式数据前固定）

| 项目 | 配置 |
|---|---|
| 两臂 | ST：publisher 单线程；MT：publisher 加一个休眠 helper |
| 分组 | 每配置 6 个独立组，每组 ST、MT、MT、ST，24 轮/配置 |
| 吞吐 | FIFO 1P2S，64/256 B，50M 条/轮，1 MiB ring，batch=1，poll-limit=64 |
| 短延迟 | FIFO 1P1S，64/256 B，attempt/planned，1M msg/s，2M 条/轮，采样每 16 条 |
| CPU | coordinator CPU0；subscriber 从 CPU1 起；publisher 紧随最后 subscriber |
| 预热 | 每配置每臂一次；另有功能 smoke，全部独立保留，不进入统计 |
| 隔离 | systemd cgroup，CPU0-3，Nice=5，MemoryHigh=640 MiB，MemoryMax=704 MiB，零 cgroup swap |

每轮保存完整命令、显式环境覆盖、客户端/输入 SHA、stdout/stderr SHA、退出状态与 cgroup
压力计数。任何运行故障均保留，不为获取理想方向重跑。不能与旧冻结客户端直接拼成产品收益。

### 3.2 判定

先验收测量有效性：所有计划运行与身份完整、ST/MT 线程状态正确、无 worker/超时/内存压力故障、
每轮发布与广播交付计数完整。吞吐计数检查不冒充 HFT 的全内容/序号校验。

报告每臂中位数、均值、CV、组内 ST/MT 比值和方向数；延迟报告各轮分位数的中位数与范围，
不池化短测分位数。组级配对统计只作为探索性证据，不作为产品验收或生产 SLA。
本轮不预设收益百分比，不因数据好坏改变矩阵，也不把 MT 成本声明为纯 `shared_ptr` 纳秒成本。

若发现稳定 MT 成本，再提出不损害生命周期的独立候选。没有证据时如实收口，不能直接删掉保活引用。
