# Publisher 尾延迟相对收益验收：2026-10-18

> 历史归档：仅记录当时版本、配置与结论，不代表当前性能或验收状态。当前汇总及下一轮任务见[最终性能测试与优化交接报告](../../performance-report.md)。

## 结论

**本轮相对收益验收失败。新产品候选已撤销，保留诊断、复跑工具、回归测试和全部原始证据。**
未将短期局部改善当作成功；实验结束时不部署、不提交、不打 tag **被否决的产品候选**。
本报告记录该次实验的历史状态，后续可以单独提交诊断工具、回归测试和失败结论。
该次实验回滚后的产品源码保持基线
`ffbf6e10fb57930cdac46f036d218b3e57556507`，不撤销该基线已经包含的历史优化。

重点配置要求两种 2P2S 突发端到端 p99.9 均降低至少 20%，其余六配置退化不超过 5%，
且三组独立 ABBA **分别满足**，所有 worker、已发布消息完整性及原计划输入完成性通过。
本轮三组均未通过；256 B 双订阅突发分别增加 **115.4%、735.7%、418.9%**。
因此按预先约定跳过有条件的八配置各 225 秒长测，不把未运行的 30 分钟写成已验收。
50 µs 门禁独立报告：候选 48 个正式阶段均未通过最差 subscriber 的 p99.9 预算。

## 候选假设与回归

独立诊断发现 publisher 成功 claim/commit 调用是亚微秒级，计划到首次尝试已出现毫秒积压；
失败 claim 中仍可能读取 `/proc/<pid>/stat`。本轮只验证一个保守候选：Reliable 字节/消息窗口
在进程探测前重读阻塞游标，并在活进程探测后重读消费进度，避免在过期快照上重复背压。

候选不改变共享布局、公共 API、死亡身份判断、注册代际验证、registration gate、claim_active、
内存序或 Latest 语义，没有缓存死亡结论。新增测试用确定性 callback 注入消费推进和代际替换，
验证同一 claim 利用安全进度、双窗口安全前缀以及替换注册必须拒绝。

候选全量 Release **20/20 CTest** 通过；定向 ASan/UBSan、TSan 各 **3/3 CTest** 通过。
定向 GTest 共 123 项，121 通过、2 项既有单帧参数不适用的批量测试显式跳过。
正确性通过不等于性能通过；失败后将产品候选和候选专属测试一起撤销，补丁保存在原始证据目录。
撤销后再次全量构建并执行 Release **20/20**、定向 ASan/UBSan **3/3**、TSan **3/3**，
全部通过；保留的诊断/汇总/编排工具 **36 项 Python 测试通过**，包含真实 CLI 汇总、
原始文件缺失、A/B affinity 不一致、汇总篡改、重复组、失败 worker 与拒绝覆盖测试。
默认 harness 重新构建及跨进程时钟/直方图 self-test 通过，产品源码与 HEAD 完全一致。

## 双口径诊断与优化边界

| 2P2S 256 B 突发 | baseline / candidate publisher 首次尝试至提交 p99.9（µs） | baseline / candidate 计划到首次尝试 p99.9（µs） | baseline / candidate 背压重试 |
|---|---:|---:|---:|
| 第一组 | 3.583 / 0.799 | 5046.271 / 9830.399 | 220849 / 245539 |
| 第二组 | 3.519 / 6.207 | 3735.551 / 38797.311 | 230634 / 338380 |
| 第三组 | 3.103 / 0.639 | 5111.807 / 31719.423 | 227777 / 241611 |

此表 publisher 指标为分别合并每 publisher 原始桶后的最大值，不是跨 publisher 合并百分位。
首次尝试至提交包含重试、payload 写入、commit 和期间抢占，不能称为纯 CPU 调用开销。
两组该指标变好时端到端仍退化，因此继续仅削减成功调用指令不足以证明目标已解决。
失败探测/重试放大、消费端进度与发布调度积压值得后续分别研究，但本次没有证明单一因果根因。

正式压测完成后另用冻结二进制分别运行 5 秒 2P2S 64/256 B 诊断：成功 claim p99.9
约 0.383–0.471 µs，commit 约 0.165–0.403 µs，额外计时只在 `--diagnostics` 开启。
失败 claim 样本按已采样消息条件采集，不是全体失败调用的均匀抽样；零样本不表示没有背压。
该独立 candidate 256 B 诊断有 2,076 条未发送，明确失败并保留，不计入正式 A/B。

另各运行一次 2 秒 `strace -f -c`，baseline/candidate 总 openat 为 579/246，
read 为 563/230。这些包含启动调用且 tracing 改变时序，不能转写为真实负载下的尾延迟收益。
`perf_event_paranoid=4` 禁止 perf 事件，本轮未修改权限，也没有 scheduler trace 或宿主级证据。
正式 baseline/candidate worker 非自愿上下文切换合计 1,008,503/1,015,264，
minor faults 1,564/1,525，major faults 均 0；三组 `/proc/stat` steal 增量均 0。
这些观察不证明宿主没有干扰，也不能断言 KVM 是本轮退化的原因。

后续优先项是可独立证伪的重试/进度诊断和有边界的慢路径工作，仍须保留死亡消费者恢复、PID 启动标识、
最慢消费者可靠背压、注册/注销与混合等待契约。registration guard 的 seq_cst、共享布局或通知协议
属于更高风险方案，本轮未弱化。任何调参或独占机器实验须另列结果，不能混入本轮固定门禁。
